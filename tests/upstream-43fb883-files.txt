# WHY THIS FILE EXISTS. run-lint.sh holds fork-added shell files to this fork's
# formatting (shfmt -i 2) and leaves upstream's files in upstream's formatting,
# so the two can still be diffed when reviewing an upstream change. It used to
# derive that split by reading a local `upstream-43fb883` git tag. This
# repository's history does not reach upstream, so there is no such tag and no
# ref to resolve — and the failure was silent: `git ls-tree` printed nothing,
# every upstream file was misread as fork-added, and shfmt failed the suite
# against files it was never meant to touch.
#
# A committed list has no such failure mode. It is a fact about a commit that
# will never change, so pinning it as data rather than deriving it from a ref is
# both correct and cheaper. Verify it against upstream at any time with:
#
#   git fetch upstream && \
#     git ls-tree -r 43fb883ac1989d962c8699afb0be37fbe69c4476 --name-only
#
